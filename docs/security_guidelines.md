## Общие рекомендации

- **Принцип наименьших привилегий**: Всегда предоставляйте только минимальные необходимые права доступа.
- **Глубокая защита**: Используйте несколько уровней защиты. Не полагайтесь только на один механизм безопасности.
- **Безопасность по умолчанию**: Настройки безопасности должны быть включены по умолчанию.
- **Проверка входных данных**: Всегда проверяйте и валидируйте все входные данные.
- **Логирование**: Ведите подробные логи безопасности для выявления и анализа инцидентов.

## Защита от XSS

Cross-Site Scripting (XSS) — это уязвимость, позволяющая внедрять вредоносный код на страницы сайта.

### Рекомендации:

- **Используйте автоэкранирование в шаблонах**: Django по умолчанию экранирует вывод в шаблонах. Избегайте использования `{{ variable|safe }}` без предварительной очистки данных.
- **Применяйте CSP**: Content Security Policy ограничивает источники, откуда могут загружаться ресурсы.
- **Очищайте пользовательский ввод**: Используйте `bleach` для очистки HTML от потенциально опасных элементов.
- **Установите заголовки X-XSS-Protection**: Включает встроенную в браузеры защиту от XSS.

```python
# Пример очистки HTML
import bleach

def clean_user_html(html_content):
    allowed_tags = ['p', 'a', 'strong', 'em', 'h1', 'h2', 'h3', 'ul', 'ol', 'li']
    allowed_attributes = {'a': ['href', 'title']}
    return bleach.clean(html_content, 
                       tags=allowed_tags, 
                       attributes=allowed_attributes, 
                       strip=True)
```

## Защита от SQL-инъекций

SQL-инъекции позволяют злоумышленникам внедрять SQL-код в запросы к базе данных.

### Рекомендации:

- **Используйте ORM Django**: ORM автоматически экранирует параметры в запросах.
- **Избегайте raw SQL**: Если необходимо использовать raw SQL, используйте параметризованные запросы.
- **Не используйте string concatenation**: Никогда не конкатенируйте строки для построения SQL-запросов.

```python
# Хороший пример (ORM)
users = User.objects.filter(username=username)

# Плохой пример (уязвимый для инъекций)
# users = User.objects.raw(f"SELECT * FROM users_user WHERE username = '{username}'")

# Хороший пример (параметризованный запрос)
from django.db import connection
with connection.cursor() as cursor:
    cursor.execute("SELECT * FROM users_user WHERE username = %s", [username])
    users = cursor.fetchall()
```

## Защита от CSRF

Cross-Site Request Forgery (CSRF) — это атака, которая заставляет пользователя выполнять нежелательные действия на сайте, где он аутентифицирован.

### Рекомендации:

- **Всегда используйте CSRF-токены**: Django имеет встроенную защиту от CSRF, всегда включайте тег `{% csrf_token %}` в формах.
- **Включите CSRF-защиту для AJAX-запросов**: Добавляйте CSRF-токен в заголовки запросов.
- **Проверяйте Referer и Origin заголовки**: Дополнительная проверка, откуда пришел запрос.

```javascript
// Пример AJAX-запроса с CSRF-токеном
const csrftoken = document.querySelector('[name=csrfmiddlewaretoken]').value;

fetch('/api/endpoint/', {
    method: 'POST',
    headers: {
        'Content-Type': 'application/json',
        'X-CSRFToken': csrftoken
    },
    body: JSON.stringify(data)
})
```

## Безопасность аутентификации

### Рекомендации:

- **Сложные пароли**: Требуйте сложные пароли от пользователей.
- **Безопасное хранение паролей**: Используйте современные алгоритмы хеширования (Argon2, PBKDF2).
- **Защита от перебора**: Ограничивайте количество попыток входа.
- **Двухфакторная аутентификация**: По возможности реализуйте 2FA.
- **Безопасные сессии**: Используйте HttpOnly и Secure флаги для cookie.

## Безопасность файлов

### Рекомендации:

- **Проверяйте тип файлов**: Используйте валидаторы для проверки загружаемых файлов.
- **Ограничивайте размер файлов**: Установите разумные ограничения на размер загружаемых файлов.
- **Проверяйте MIME-типы**: Используйте библиотеку `python-magic` для проверки фактического типа файла.
- **Защита от SVG-инъекций**: Проверяйте SVG-файлы на наличие вредоносного JavaScript.

## HTTPS и безопасность транспортного уровня

### Рекомендации:

- **Всегда используйте HTTPS**: Весь сайт должен быть доступен только по HTTPS.
- **Настройте HSTS**: HTTP Strict Transport Security заставляет браузеры использовать только HTTPS.
- **Безопасные cookie**: Используйте флаги Secure и HttpOnly для cookie.
- **Современные протоколы**: Используйте TLS 1.2 и выше, отключите устаревшие протоколы.

## Продакшен-настройки

### Рекомендации:

- **DEBUG = False**: Всегда отключайте режим отладки в продакшене.
- **Секретные ключи**: Храните секретные ключи в переменных окружения или в файле .env.
- **Ограниченный доступ к админке**: Ограничьте доступ к админ-панели по IP или используйте VPN.
- **Защита от DDoS**: Используйте CDN или специализированные сервисы защиты.

```python
# Пример настроек безопасности для продакшена в settings.py
DEBUG = False
ALLOWED_HOSTS = ['example.com', 'www.example.com']

SECURE_HSTS_SECONDS = 31536000  # 1 год
SECURE_HSTS_INCLUDE_SUBDOMAINS = True
SECURE_HSTS_PRELOAD = True
SECURE_SSL_REDIRECT = True
SESSION_COOKIE_SECURE = True
CSRF_COOKIE_SECURE = True
X_FRAME_OPTIONS = 'DENY'
```
